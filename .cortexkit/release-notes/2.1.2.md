## What's fixed

- **Requests no longer fail on a busy settings file.** Under heavy load a request could fail with `Timed out acquiring native-relay lock for …/anthropic-auth-vault-settings.json`. Every request read the relay settings under the same lock their writer uses, and a lock that couldn't be taken in time failed the request. Requests now read the relay settings without a lock. A relay change stamps the settings and the relay token together, and a request that reads a mismatched pair during a change refuses locally instead of sending the token anywhere.
- **Session pins never hold up a request.** Choosing the account for a session waited up to five seconds for the session-pin file and could fail without it. The account is now chosen from the saved pins without a lock, and the pin is saved in the background. Resetting a session still reaches the file.

Checked on OpenCode 1, OpenCode 2 and Pi: a request with a valid login takes no lock before it is sent. Locks that protect credential refreshes are unchanged.

To upgrade, quit OpenCode and run `npx @cortexkit/opencode-anthropic-auth@2.1.2 setup`, or change the version in your OpenCode config.
