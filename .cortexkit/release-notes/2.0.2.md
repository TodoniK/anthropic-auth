## What's fixed

- **Session pins after upgrading to 2.0.** With local accounts, OpenCode 1 and OpenCode 2 now read the same session-routing file that the 2.0 setup migration filled, as Pi already did. Before, they read a different file, so after upgrading each existing conversation picked an account again and rebuilt its prompt cache. On the first request after this update, pins saved since the upgrade are merged in once, without replacing newer ones. Vault mode was not affected.
- **Tool calls with names that were never sent.** Claude sometimes calls a tool by a shortened or misspelled name, such as `mcp_Search`. The plugin now maps a response's tool names back using only the tools that request actually declared. A guessed short name maps back only when exactly one declared tool matches it. Before, it guessed an AFT tool from a fixed list. That guess could route the call to the wrong tool, and it even rewrote a correctly called tool named `search` to `aft_search`. If a name can't be mapped back without risk of picking a different tool, the response stops with a clear error instead of running it. Tool arguments are never changed (#286).

## Compatibility

- Pi 1.x is supported (tested with Pi 1.1), alongside Pi 0.86.
- The OpenCode sidebar is built for OpenTUI 0.6.

## Upgrading

From 2.0.x, update the plugin and restart OpenCode or Pi. No setup step is needed.

From 1.x, follow the 2.0.0 upgrade steps: quit every OpenCode, LiteCode and Pi process, then run `bunx @cortexkit/opencode-anthropic-auth@2.0.2 setup`.
